# 基于 STM32 的智能多任务网络天气时钟系统 (Smart Multi-Task Network Weather Clock)

## 📌 项目简介
本项目是一款独立开发、具备工业级稳定性的低功耗智能桌面天气时钟终端。系统基于 **STM32F407VET6** 纯裸机环境构建，彻底摒弃了传统的死等式阻塞设计，使用了一套**轻量级非阻塞多任务时间片轮询架构**，在无 RTOS 环境下完美解决了任务并发、临界区保护与数据原子性读取问题。

通过高度模块化的**工程分层体系（APP-Device-Driver-System）**，系统成功整合了本地高精度 RTC 走时、AHT20 环境传感、基于 ESP-AT 协议的无线网络通信以及深度优化的 LCD 动态 UI 渲染引擎，实现了毫秒级响应的并发调度。

│   ├── mloop.c   # 自研核心时间片轮询主循环调度器
│   └── wireless.c# 无线网络应用层交互固件
├── devices/      # 【外设组件层】通用组件与应用层协议封装
│   ├── espat.c   # ESP32-C3 模块 AT 指令集解析状态机
│   └── weather.c # HTTP GET 气象数据请求流式解析器

│   ├── lcd.c     # 基于硬件 SPI2 (ST7789) 的流式传输与渲染优化
│   ├── aht20.c   # 模拟 I2C 硬件抽象与温湿度传感器驱动
│   ├── rtc.c     # 芯片内置高精度实时时钟底层驱动
│   └── serial.c  # USART 串口流式驱动及环形缓冲区 FIFO 适配
├── system/       # 【系统基准层】内核级硬件时基与原子时间戳

## 🛠️ 核心技术亮点与深度重构

虽然本项目的部分底层协议与基础字库源自开源组件，但在系统集成与固件开发过程中，针对硬件带宽与裸机并发瓶颈进行了大量的底层重构与极致优化：

### 1. 异步多任务状态机与非阻塞调度 (消除系统阻塞)
* **痛点**：传统裸机开发中频繁使用 `delay_ms()` 导致 CPU 空转，网络请求或传感器采样时全系统“假死”。
* **重构方案**：利用 Cortex-M4 内核的 **SysTick 定时器** 寄存器配置 1ms 硬件时基中断。将传感器采集、网络请求、UI 刷新等高耗时任务拆分为**异步有限状态机 (FSM)**。
* **效果**：系统主循环 (`mloop.c`) 仅轮询时间戳及状态标志，彻底消除死等阻塞，任务切换上下文开销接近于零，实现毫秒级响应。

### 2. 基于 Sequence Lock (序列锁) 的原子级 64 位时间戳机制
* **痛点**：在 32 位 MCU 中读取 64 位全局时间戳（`uint64_t`）需要分两次读取高低 32 位，在频繁的中断环境下极易发生时钟滴答撕裂（Tearing）。
* **重构方案**：在 `system/delay.c` 中引入了无锁双读校验（**Sequence Lock**）机制。读取前与读取后双向校验时钟溢出标志，若两次结果不一致则触发重读。
* **效果**：在**不关闭全局中断**的前提下，保证了 `cpu_now()` 接口读取 64 位系统滴答的绝对原子性，避免了临界区死锁并维持了系统的高实时性。

### 3. 零显存 (0-VRAM) 消耗的局部差分刷新与变宽字库引擎
* **痛点**：STM32F407VET6 内部 SRAM 紧张（192KB），无法开辟全屏 VRAM 显存帧缓冲区，导致全屏刷新时 SPI 总线带宽不足，屏幕闪烁严重。
* **重构方案**：
  * **变宽排版**：全面重构字符渲染引擎，放弃传统的死板等宽排版，通过实时读取字库物理点阵阵列的真实物理宽度进行**动态步进计算**，实现动态边界换行防御与完美的像素级居中。
  * **差分局部刷新**：利用 `snprintf` 生成数据掩码，在文本内容变化时通过**像素级变化过滤器**精确计算变更区域（Bounding Box），仅向 ST7789 驱动芯片发送局部显存映射区域。
* **效果**：在 **0 显存开销** 的极端条件下，将硬件 SPI 吞吐利用率优化至极致，彻底消除了屏幕局部刷新的闪烁感。

### 4. 串口流式驱动与网络应用层 AT 指令状态机
* **痛点**：通过 Wi-Fi 模块（ESP32-C3）获取的天气 JSON 数据包往往远大于单次串口接收缓冲区，且数据包中夹杂大量冗余信息。
* **重构方案**：基于 USART 串口流式驱动，配合 DMA/环形缓冲区构建底层接收。在上层编写**定制化 AT 指令集解析状态机**，采用**增量式数据掩码解析过滤算法**，在数据流边接收的过程中同步进行关键字过滤和 JSON 裁剪，提取出核心天气指标，最后通过 SNTP 协议实施网络精密对时。
* **效果**：极大地节省了系统动态内存开销，避免了大数据包引起的缓冲区溢出风险，确保了网络通信的长效稳定。

## 🖥️ 硬件与开发环境
* **核心板**：STM32F407VET6 (ARM Cortex-M4，主频 168MHz)
* **显示介质**：2.4寸 LCD 屏幕 (ST7789 驱动芯片，240x320 分辨率)
* **传感器**：AHT20 温湿度传感器 (I2C 总线)
* **无线模组**：ESP32-C3 / ESP-01S (使用标准 ESP-AT 固件)
* **开发链工具**：Keil MDK uVision v5.38 + STM32F4xx 固件库 
* **调试仪器**：逻辑分析仪 (用于 SPI/I2C/USART 时序捕捉与协议分析)、万用表、串口助手
